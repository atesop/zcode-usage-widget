# GLM 用量组件任务栏贴条设计（主屏试水）

> 状态：已批准蓝图的形式化落盘（2026-10-27 拍板：贴条方案 · 主屏试水），待老大确认本文档后派生 openspec change
> 修订历史：
> - 2026-10-27 v1 初版：从调研呈报 + 三问澄清结论（范围/内容/交互）整理落盘

## 1. 问题定义

GLM 用量 widget（WPF/PS5.1 悬浮窗）当前停靠副屏右下角，只有坐在副屏前才看得到。诉求：让主屏也能常看用量，且形态融入 Windows 任务栏（两块屏最终都要可见）。

## 2. 调研结论（含否决方案，2026-10-27）

本机环境：build 26300（Win11 代任务栏代码库），标准底部任务栏——图标居中、左端天气按钮、右端托盘+时钟（注册表 TaskbarAl=1 已核实）。主屏任务栏左端空白实测约 400+px（居中图标群左侧、天气按钮右侧）。

| 方案 | 结论 | 理由 |
|---|---|---|
| DeskBand 真嵌入 | ❌ 否决 | 第三方 DeskBand 自 Win10 1803 移除，Win11 无官方接口；只能 ExplorerPatcher/Windhawk 系统魔改，公司机器不可接受 |
| 纯托盘图标 | ❌ 否决 | 信息容量太小（无文字空间），全屏应用时同样不可见 |
| 双屏角落重复悬浮窗 | ⚪ 兜底保留 | 可行但不解决"融入任务栏"诉求 |
| **任务栏贴条（推荐，已批准）** | ✅ | 无边框置顶小条贴任务栏左端空白（TrafficMonitor 同款思路）；左端是死区零遮挡；双屏通用（每屏一条共享查询） |

## 3. 已批准方案总览（2026-10-27 三问澄清后）

| 决策点 | 结论 |
|---|---|
| 方案 | 任务栏贴条：48px 高无边框置顶小条，贴主屏任务栏左端空白 |
| 范围 | **主屏试水**，验证通过后 v2 扩双屏 |
| 内容 | 三订阅横排 chip：01-w / 02-z / 03-a 各自 5 小时窗口已用 %，颜色随阈值绿/黄/红（同现有状态栏）；悬停 ToolTip 看剩余/重置 |
| 交互 | 点击贴条弹出详情面板（三订阅剩余/总量/重置时间），再点或点外部收起 |
| 共存 | 试水期主屏贴条与副屏角落悬浮窗**共存，共享一次查询**（两个消费方）；v2 双屏贴条齐后再让悬浮窗退役 |

## 4. 架构设计

单窗模型 → **1 查询 + N 显示面**：

```
DispatcherTimer 定时查询（不变，解析三订阅 JSON）
        │ 刷新事件分发（共享状态对象）
        ├── 悬浮窗（副屏角落，试水期保留，现有逻辑不动）
        ├── 主屏贴条（新增：横排 chip）
        └── 详情面板（新增：打开时读共享状态快照）
```

- 查询与数据组装逻辑（订阅解析、百分比、警示色、ToolTip 文案）复用现有代码，不动数据面
- 新增贴条窗口与详情面板两个显示面，从共享状态对象取数渲染
- 贴条模式由 json 配置开关控制，默认关闭（不影响现有用户行为）

## 5. 组件设计

### 5.1 贴条窗口

- WPF Window：WindowStyle=None、ResizeMode=NoResize、Topmost=true、ShowInTaskbar=false
- 尺寸：高 48px 对齐任务栏高；宽度按内容自适应（三 chip + 内边距），不超过左端空白实测值
- 定位：`Shell_TrayWnd` GetWindowRect 取主屏任务栏矩形 → 贴左端、垂直居中；SetWindowPos 走**物理像素**路径（复用 commit 531d843 的 Invoke-Redock 机制，扩展为通用重贴）
- 任务栏矩形校验：每次刷新周期比对任务栏矩形，变化即重贴（覆盖用户改任务栏设置/转屏场景）

### 5.2 chip 渲染

- 复用现有状态栏 chip 逻辑，横排化：每 chip 一行"简写 + 已用 %"（两行小字排布在实现时按 48px 高度定夺，spec 只约束信息与着色）
- 查询失败时 chip 标 ✗（同现有状态栏语义）

### 5.3 详情面板

- 点击贴条弹出（贴条上方），无边框 WPF 窗口/Popup
- 内容：三订阅剩余/总量/重置时间（数据组装复用悬浮窗第二行逻辑）
- 收起：再点贴条或点面板外部

### 5.4 全屏自动隐藏

- 检测前台窗口是否全屏（MonitorFromWindow + 窗口矩形 vs 屏幕矩形）；全屏时贴条隐藏，退出恢复
- 最大化 ≠ 全屏，只躲真全屏（TrafficMonitor 先例）

### 5.5 explorer 重启自愈

- RegisterWindowMessage("TaskbarCreated") 广播 → 重新定位贴条（任务栏窗口被重建）

## 6. 数据流

定时查询（现有）→ 解析三订阅（现有）→ 写共享状态对象（含最近成功快照与时间戳）→ 刷新事件 → 各显示面重渲染。详情面板打开时读快照，不单独发查询。

## 7. 错误处理

| 场景 | 行为 |
|---|---|
| 查询失败 | chip 标 ✗；详情面板显示最近成功快照 + 时间戳 |
| 任务栏矩形获取失败 | 贴条隐藏 + 日志，下个刷新周期重试 |
| explorer 重启 | TaskbarCreated 消息触发重贴 |
| 全屏应用 | 贴条自动隐藏，退出恢复 |

## 8. 测试与验证

windows/ 下为 PS 脚本，无单测框架先例，验证以运行冒烟为主（逐条验证命令落在 openspec change 的 tasks.md）：

1. 语法/编译检查（PSParser 或 dotnetsource 等价检查）
2. 启动冒烟：贴条出现在主屏任务栏左端、位置/高度正确、三 chip 渲染与悬浮窗一致
3. 点击弹详情面板、再点收起
4. 模拟查询失败（断 token/断网）→ chip ✗、详情面板出快照时间戳
5. 全屏一个窗口 → 贴条隐藏；退出 → 恢复
6. explorer 重启场景与用户约时间做（曾因自动操作扰民回滚过，见 checkpoint 史）

## 9. 影响面与分期

## 10. 风险与开放问题

- 副屏任务栏形态未实测（v2 第一步处理，本次不做）
- 全屏检测的边界阈值（边框几像素容差）实现时定
- 任务栏 autohide 场景未测（本机任务栏正常可见，用户截图证实；autohide 时贴条跟随策略 v2 再议）
- 贴条与任务栏左端 hover/拖拽冲突：理论上死区无冲突，冒烟实测确认
- WSL→powershell 探针是 ÷1.5 虚拟化视图，GUI 会话进程才是真实物理像素；跨进程验几何必须换算（memory：`wsl-ps-dpi-virtualized-geometry`）
